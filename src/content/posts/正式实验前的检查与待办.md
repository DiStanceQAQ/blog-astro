本页将“接下来做什么”转换为可验证的任务。本次只整理知识库，没有修改项目代码、替换天气文件或启动实验。

## P0：先阻止试跑数据进入正式结论

| 待办 | 验收条件 |
|---|---|
| [ ] 隔离 smoke 与 formal 模式 | 正式模式遇缺雨、错网格、断日期立即拒绝；试跑标志不被静默清除 |
| [ ] 保留全缺失降水组 | 构造全缺雨量日，转换后仍为缺失且不能通过正式质检 |
| [ ] 保留真实日期 | 删除中间一天后测试，后续天气不能前移；明确补齐策略或拒绝运行 |
| [ ] 移除跨网格静默兜底 | 请求不存在网格，必须报出对应单元和缺失网格 |
| [ ] 强制检查 WRF 完成证据 | 正式晋升入口缺完成日志或标志时不可通过 |
| [ ] 检查逐网格完整生长季 | 不能只靠总体行数和网格覆盖率；每网格与预期日历逐日比对 |
| [ ] 固定气象单位与聚合规则 | 温度、降水、短波、风高、ET0 和时区都有元数据与样例测试 |
| [ ] 动态生成质量标签 | 标签由实际输入和验证状态导出，不写死；记录模型真实版本 |

对应本地 S07 的 `build_weather_wrf_csv`、`finalize_wrf_weather`、`run_baseline`。这些是静态代码检查发现的待处理风险，不表示本次已复现每种错误。

## P1：把试点底座变成可信样本

- [ ] 对 866 个候选与 861 个成员做差集，保存每个排除原因及面积。
- [ ] 检查保留面积最大的分层是否系统遗漏特殊地块；记录数量/面积/环境覆盖。
- [ ] 核对 58 个网格的实际空间归属，抽查跨格和边界地块；评估最近邻与叠置方法差异。
- [ ] 定义 2019/2023 到 2020 的稳定地块筛选规则，单独标记无法确认地块。
- [ ] 检查土壤各层参数和默认类别比例，补充根区依据与初始水分敏感性分析。
- [ ] 核实定额版本、净毛口径、作物和灌溉方式；不能将 345 mm 默认值视为所有地块已正确匹配。

## P2：完成可发表的作物基线

- [ ] 将合格天气接入少量代表单元，复核无灌溉、基准、高触发三策略。
- [ ] 检查成熟/收获日期和季节终止，避免因输入不完整而提前结束。
- [ ] 对物候、冠层、ET、产量选择有依据的校准与独立验证资料。
- [ ] 验证高温与缺水响应的实际实现，明确不可模拟或未校准过程。
- [ ] 在正式条件下再覆盖全部入选响应单元，保留失败与质量分层结果。

验收标准应在看最终结果前确定，并根据观测误差和应用需求给出依据；不在此凭空写一个统一“RMSE 必须小于某数”的门槛。

## P3：再进入风险与优化

- [ ] 决定采用真实多年份还是设计扰动情景，并明确权重和适用表述。
- [ ] 实现与论文一致的干热定义及配对损失参照。
- [ ] 比较响应单元数量与逐地块抽样结果，确定压缩误差。
- [ ] 冻结代理训练/验证/测试分组，排除试跑标签。
- [ ] 完成 Pareto 候选过程模型回代，重新检查约束和支配关系。
- [ ] 在留出情景下比较基准与候选，才形成策略推荐。

## P4：用已验证结果驱动系统

先实现地块查询、时序和基准—策略比较；再做 UE 样板田表现。系统必须显示来源、时间和质量标志，不能用精细画面掩盖粗尺度或低可信输入。

## 需要后续补齐的证据，不必先阻塞知识整理
